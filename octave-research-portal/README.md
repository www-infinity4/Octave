# Octave Research Portal

Octave Research Portal restores the earlier Infinity AI terminal as a dedicated research workspace and connects it to the newer Infinity token architecture.

## Recovered terminal lineage

The portal is based on the recovered `infinity-ai-terminal.html` design that used a dark JetBrains Mono terminal, live search indicator, knowledge graph, stance/confidence growth, search log, `i` input-terminal / `j` output-terminal / `k` portal architecture, and free-search sources such as Wikipedia, DuckDuckGo Instant Answers, and Wikidata.

Octave keeps that terminal-first interaction model but changes the purpose from a general chat terminal into a token-aware research portal.

## Research model

Every research session may produce two durable streams:

1. **PROJECT_RESEARCH** — research centered on the selected token/project, its commit lineage, dependencies, unanswered questions, evidence, tests, and build opportunities.
2. **INFINITY_DISCOVERY_RESEARCH** — a controlled-serendipity research stream that deliberately explores another token, repository, or outside domain and records the relationship initially as `EXPLORATORY_LINK` until evidence supports something stronger.

The portal should never invent citations. Search results and sourced facts remain separate from inferred connections and user-defined theory.

## Color-action grammar

The terminal exposes the shared Infinity color language:

- **GREEN — ENGINEER**: use token B to build or advance token A.
- **BLUE — IMPORT**: bring a missing component, form, interface, dataset, media item, or capability from B into A.
- **YELLOW — RESEARCH / EXTRACT**: retrieve and extract information needed by A.
- **ORANGE — DECIDE**: present an evidence-informed choice after Yellow research.
- **RED — ROUTE / FORK**: expose two or more legitimate future paths without deleting the road not taken.
- **PURPLE — ASSIMILATE**: combine imports and alternate routes into a larger architecture.

Color is an action/intention layer, not a permanent universal category. A token can render differently for different users while its canonical commit/token facts remain unchanged.

## Token-aware terminal

The terminal can work from:

- Commit Token ID / full Git SHA
- four-hash token envelope
- Living Token research streams
- user profile features and interaction history
- Timelines/symbol realms
- prior Action Token paths
- related repositories
- existing research-library entries

A user can enter ordinary research text or token commands such as:

```text
research electron capture
open IC-7EE4-9BE7-044B-1A28
green oxygen extraction interface
blue import oxide pump
yellow lithium proton fusion evidence
red storage architecture
purple assimilate display + storage
random discovery
```

These commands are intended to become Action Tokens when the shared ledger API is deployed.

## Novelty engine

New research should not simply repeat the last article. Candidate research assignments are generated by combining:

- current token terms
- profile interests/skills
- unresolved project questions
- prior searches
- token lineage
- recent color-action paths
- a rotating cross-domain term
- optional user-supplied direction

Previously used query hashes, article hashes, source-set hashes, and close title/topic combinations should be excluded or strongly down-ranked.

The novelty layer chooses the *question*. Evidence still comes from real sources.

## Stance / confidence

The recovered terminal's stance progression is retained as a UI indicator:

`LEARNING → SEARCHING → REASONING → INFORMED → ANALYTICAL → MONGOOSE-COLD → VECTOR-TRUTH`

This is a user-interface confidence/research-completeness indicator, not proof that a claim is true. Claim-level evidence remains tagged independently as `OBSERVED`, `INFERRED`, `EXTERNALLY_VERIFIED`, or `USER_DEFINED`.

## Local-first operation

The initial browser implementation can retain a local knowledge graph and search history in localStorage/IndexedDB. Production mode should synchronize through the central INFINITY research/token service so a user's profile, wallet, research history, token unlocks, and Action Tokens follow them across participating repositories.

## Shared local research runtime

The portal now uses `research-runtime.js` as its adapter to the shared Infinity loopback gateway at `http://127.0.0.1:11435` (overridable with `window.INFINITY_AI_BASE_URL`).

- `REASONER` adds an optional local Gemma synthesis labeled `INFERRED`.
- `TOOL_ROUTER` proposes the selected color action but always returns `executed: false`; the application must validate and execute it separately.
- If the gateway is unavailable, Wikipedia/Wikidata source retrieval and the deterministic two-stream summary remain usable.
- Captured source URLs are stored separately from model prose. A model response cannot promote itself to `EXTERNALLY_VERIFIED`.

Each research record computes canonical SHA-256 hashes for the normalized query, sorted source set, article, token lineage, and user path. The local catalog marks a repeated query/source/article as `DUPLICATE` and retains the earlier record ID. FNV hashes remain only for legacy UI compatibility; they are not the durable novelty identity.
